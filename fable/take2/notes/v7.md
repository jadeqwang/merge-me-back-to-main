# v7 re-timing and plates (take two)

State 2026-11-13: DONE. Code committed; renders in `work_fable/` (git-ignored).

## What was added
- `fable/tools/render.mjs`
  - `--warp analysis_v3/warp_v2_to_v3.json`: all times (`--from/--to/--stills/--sheet`) are NEW song time. The page gets `ENGINE.warp(newT) -> oldT`:
    beats[] (new -> old) piecewise linear by beat index (the table is monotone), end slopes extrapolated outside it; the show clamps at the old film end
    (old 282.4999), so the last ~3.0 s of new time (new > 279.81) hold the old film's last frame. Motion-blur sub-samples are spread in new time, then mapped.
    `--audio` with `--warp` muxes `inputs/Merge (keychange down).wav` (without it: `Merge.mp3`, unchanged). Without `--warp` nothing changes.
  - `--frames DIR`: instead of an mp4, writes `f_%05d.jpg` (frame number = absolute frame at the output fps, so `--from 0` gives f_00000 = t 0). `--jpgq 2` (ffmpeg qscale; default 2 ~ q95).
- `fable/engine/src/main.js`: page flags `notype=1` (drops the show's `type` lines) and `nohud=1` (drops `hud` and the `overlay` 2D layer: terminal card, credits). Also the warp hook (`wp`).
- `fable/take2/tools/v7/syncstrip.sh` (sync strip, test 5), `fable/take2/tools/v7/sheets.sh` (1 fps contact sheets from a frame folder).

## Commands
    R="node fable/tools/render.mjs --show /fable/show/main.js --res 1920x1080 --warp analysis_v3/warp_v2_to_v3.json --q notype=1&nohud=1 --mb 4"
    # drop, test 5 (6 workers, 93 s):
    $R --from 150 --to 182 --workers 6 --crf 16 --preset medium --audio --mp4 work_fable/take2/tests/v7_retime/drop_retimed.mp4
    # full plates (8 workers, 512 s = 16.6 fps at 1080p, mb 4):
    $R --from 0 --to 282.8 --workers 8 --frames work_fable/take2/v7/full
    fable/take2/tools/v7/sheets.sh ; fable/take2/tools/v7/syncstrip.sh
(quote the `--q` value in a real shell: `--q "notype=1&nohud=1"`.) Page boot costs about 1-4 min with many workers (cast sim per page).
